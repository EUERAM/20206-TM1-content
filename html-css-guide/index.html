0. Prepare your workspace

Before writing HTML or CSS, prepare your tools and open the project folder in Visual Studio Code. A project is a collection of related files and folders, not just one HTML file.

Install Visual Studio Code and useful extensions

Install Visual Studio Code, then open the Extensions view using the square icon in the Activity Bar or Cmd+Shift+X on Mac (Ctrl+Shift+X on Windows). Search for and install:

  • Prettier - Code formatter (esbenp.prettier-vscode) — formats HTML, CSS and other supported files consistently.
  • Live Server (ritwickdey.LiveServer) — opens your page in a browser and refreshes it when you save changes.
  • Auto Close Tag (formulahendry.auto-close-tag) — adds a closing HTML tag when you finish an opening tag.
  • Auto Rename Tag (formulahendry.auto-rename-tag) — updates a matching closing tag when you rename an HTML tag.
  • Path Intellisense (christian-kohler.path-intellisense) — suggests file and folder paths as you type them.

Only install extensions you need, and check the publisher and extension details in the VS Code Marketplace before installing. VS Code's built-in Emmet also expands common HTML abbreviations; for example, type ! in an empty HTML file and press Tab.

Format your code when you save

  1. Open Settings with Cmd+, on Mac or Ctrl+, on Windows.
  2. Search for Editor: Format On Save and turn it on.
  3. Search for Editor: Default Formatter and choose Prettier - Code formatter.

Now Prettier formats supported files each time you save. You can also format a file manually with Shift+Option+F on Mac or Shift+Alt+F on Windows.

Open the whole project folder (not just a file)

Important: open the folder that contains your website in VS Code. Do not open only index.html or style.css. Opening the folder lets VS Code show all project files together, and helps relative paths and Live Server work as expected.

  1. Create or locate one folder for your website, for example my-website.
  2. In VS Code choose File > Open Folder… and select my-website. On Mac you can also press Cmd+O only if the dialog is set to open a folder; the menu command is the clearest option. On Windows use Ctrl+K, then Ctrl+O.
  3. In the Explorer on the left, create and open files inside that folder, such as index.html and css/style.css.
  4. To preview the page, right-click index.html in the Explorer and choose Open with Live Server. 
my-website/              <!-- open this folder in VS Code -->
├── index.html
└── css/
    └── style.css

If you see only one file in the Explorer, you may have opened a file instead of the project folder. Close that window, then use File > Open Folder… to open the folder that contains your project.

1. Creating an HTML file & its tag structure

Create a text file, save it with the .html extension (e.g. index.html) and start from this skeleton: 

<!DOCTYPE html>                          <!-- tells the browser: this is HTML5 -->
<html lang="en">                         <!-- root element -->
  <head>                                 <!-- info about the page (NOT visible) -->
    <meta charset="UTF-8">               <!-- accents and special characters -->
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My page</title>               <!-- text of the browser tab -->
  </head>
  <body>                                 <!-- everything visible goes here -->
    <h1>Hello world</h1>
    <p>My first paragraph.</p>
  </body>
</html>

Tip for Visual Studio Code: in an empty .html file, type ! and press Tab (or Enter) to generate this basic structure automatically (Emmet shortcut).

Anatomy of a tag

<a href="page.html">Click</a>

  • Opening / closing tag: <a> … </a>
  • Attribute: href="…" (name + value)
  • Content: what is between the tags
  • Void tags have no closing: <img>, <br>, <meta>

Nesting (tags inside tags)

<body>
  <header>
    <h1>Title</h1>
  </header>
  <main>
    <p>Text with <strong>bold</strong>.</p>
  </main>
</body>

Always close the last tag you opened first, and indent children.

3. Writing HTML tags: from outside to inside

Don't type the page top to bottom without thinking. Build it in layers: first the big outer boxes, then group the contents, and finally fill each group with meaningful content.

Step 1: the outer skeleton

<html lang="en">
  <head></head>
  <body></body>
</html>

Step 2: the big areas of the page (inside body)

<body>
  <header></header>
  <main></main>
  <footer></footer>
</body>

Step 3: group the contents that belong together

<main>
  <section>            <!-- one topic -->
    <article></article>   <!-- one independent item (post, card) -->
    <article></article>
  </section>
  <div class="gallery"></div>   <!-- div = group with no special meaning, used for styling -->
</main>

Step 4: fill with meaningful content

<article>
  <h2>Why learn CSS?</h2>                     <!-- title of the group -->
  <p>CSS makes pages <strong>beautiful</strong>.</p>
  <ul>                                         <!-- a list of things = ul + li -->
    <li>Colours</li>
    <li>Layouts</li>
  </ul>
  <img src="img/css.png" alt="CSS logo">       <!-- alt describes the image -->
  <a href="about.html">Read more</a>
</article>

Meaningful ✓

<header>
  <h1>My blog</h1>
  <nav>
    <ul>
      <li><a href="index.html">Home</a></li>
    </ul>
  </nav>
</header>

"Div soup" ✗

<div class="top">
  <div class="big-text">My blog</div>
  <div>
    <div><span>Home</span></div>
  </div>
</div>
  • One <h1> per page, then h2, h3… in order (don't skip levels just for size, that's CSS's job).
  • Text goes in <p>, never loose inside a <div>.
  • A list of items → <ul>/<ol> with <li>.
  • Every <img> needs alt.
  • Prefer a semantic tag; use <div> only when none fits.
  • Indent 2 spaces per level, write tags in lowercase, and always close what you open.

How to write comments in HTML

A comment is a note for humans. The browser ignores it.

<!-- This is a one-line comment -->

<!--
  This is a comment
  on several lines
-->

<!-- Comment out code to disable it temporarily:
<p>This paragraph will NOT be shown</p>
-->

<!-- ========== HEADER ========== -->
<header>...</header>
<!-- ========== /HEADER ========== -->

VS Code shortcut: select the lines and press Cmd+/ (Mac) or Ctrl+/ (Windows) to comment/uncomment them.

  • Comments are not displayed, but anyone can read them with "View source". Never write passwords or private data.
  • Don't nest comments (a <!-- --> inside another).
  • Use them to explain why or to mark where a big block starts and ends, not to repeat obvious things.

5. Block tags vs inline tags

Block elements start on a new line and take the full width. Inline elements stay in the text flow and only take the space they need.

Block: div, p, h1, ul, section…

div (block)

p (block)

h4 (block)

Each one sits on its own line. width, height, margin and padding work fully.

Inline: span, a, strong, em, img…

span a strong em another span

They flow side by side like words. width and height are ignored; vertical margin has no effect.

Inline-block and changing the type with display

inline-block 1 inline-block 2 inline-block 3

Flows like inline, but accepts width/height like block (here: width: 130px; height: 50px). 

/* any element can change type */
span { display: block; }         /* now acts like a block */
div  { display: inline; }        /* now acts like inline */
span { display: inline-block; }  /* flows + accepts size */
.hidden { display: none; }       /* removed from the page */

Rule of thumb: blocks are the boxes of the page, inline elements are pieces inside a text. 

<p>This is a block paragraph with a <a href="#">link</a> and some <strong>bold</strong> (inline).</p>

Result: This is a block paragraph with a link and some bold (inline).

6. Links: internal, external and anchor

All links use <a href="…">. What changes is the value of href.

Internal

Another page of your website. Use a relative path. 

<a href="about.html">About</a>
<a href="pages/contact.html">Contact</a>
<a href="../index.html">Home</a>

External

A different website. Use the full URL with https://. 

<a href="https://developer.mozilla.org"
   target="_blank"
   rel="noopener">MDN</a>

Try it: MDN Web Docs

target="_blank" opens a new tab. Add rel="noopener" for safety.

Anchor

Jumps to an element in the same page that has that id. 

<a href="#folders">Go to folders</a>

7. Linking an external CSS file

Write your styles in css/style.css and link it inside the <head> of every page. 

<head>
  <link rel="stylesheet" href="css/style.css">
</head>
  • rel="stylesheet": says the file is a stylesheet.
  • href: the path to the file (see section 2).
  • If styles don't apply: check the path, the filename and the .css extension.
  • The page you are reading uses exactly this: <link rel="stylesheet" href="css/style.css">.

Other ways exist (inline style="…" or a <style> tag), but an external file lets you reuse one design across many pages.

8. Writing styles: from outside to inside

Like HTML, write CSS in layers: start with rules for the whole page, then the big areas, then each component, and finally the small elements inside it. Later rules refine the earlier ones.

Step 1: global rules (whole page)

:root { --primary: #4f46e5; }          /* variables (colours) to reuse */
* { box-sizing: border-box; }           /* applies to everything */
body { margin: 0; font-family: 'Poppins', sans-serif; color: #1f2937; }

Step 2: the big areas

header { background: var(--primary); color: white; padding: 20px; }
main   { max-width: 900px; margin: 0 auto; }
footer { text-align: center; padding: 30px; }

Step 3: components (a class per block)

.card { background: white; border-radius: 12px; padding: 20px;
        box-shadow: 0 4px 12px rgba(0,0,0,.1); }

Step 4: the elements inside the component

.card h2 { margin-top: 0; color: var(--primary); }
.card p  { line-height: 1.6; }
.card a  { color: var(--primary); }

Step 5: states and screen sizes (last)

.card:hover { transform: translateY(-4px); }

@media (max-width: 600px) {
  .card { padding: 12px; }
}

Result of steps 3 & 4

A card styled from the outside in: first the box, then what is inside.

Read more

Order inside one rule

.card {
  /* 1. layout  */ display: flex; position: relative;
  /* 2. box     */ width: 300px; padding: 20px; margin: 10px; border: 1px solid #ddd;
  /* 3. text    */ font-size: 1rem; color: #333;
  /* 4. visual  */ background: white; border-radius: 12px;
  /* 5. extras  */ transition: .3s;
}
  • General first, specific later: the same property written later wins when selectors are equally strong.
  • Write one rule per line of thinking: selector, {, one declaration per line, }.
  • Every declaration is property: value; (don't forget the ;).
  • Keep the stylesheet in the same order as your HTML (header, main, footer).

How to write comments in CSS

/* This is a one-line comment */

/*
  This is a comment
  on several lines
*/

/* ---------- HEADER ---------- */
header { background: navy; }

.card {
  color: black;
  /* border: 1px solid red;   ← disabled for now */
  padding: 10px;              /* comment at the end of a line */
}

CSS only has /* … */. The // comments of other languages and <!-- --> of HTML do not work inside a .css file (and /* */ doesn't work in HTML text). Same shortcut as HTML: Cmd/Ctrl+/.

9. Resetting the default HTML styles

Every browser applies its own default styles (a "user agent stylesheet"): body has an 8px margin, h1 is big and bold, ul has bullets and padding, links are blue and underlined… and they differ slightly between browsers. A reset removes them so you start from a clean, predictable base.

Simple reset (put it at the TOP of your style.css)

/* 1. Box model: width/height include padding and border */
*, *::before, *::after {
  box-sizing: border-box;
}

/* 2. Remove default margins and padding */
* {
  margin: 0;
  padding: 0;
}

/* 3. Common elements */
body   { line-height: 1.5; font-family: sans-serif; }
ul, ol { list-style: none; }
a      { color: inherit; text-decoration: none; }
img    { max-width: 100%; display: block; }
button, input, textarea { font: inherit; }

Why do it?

  • Your page looks the same in Chrome, Firefox, Safari…
  • No surprise margins: you decide all the spacing.
  • box-sizing: border-box makes sizes easier to calculate (see the box model section).

Reset rules go first in the file, so your own styles below can override them. Ready-made resets also exist: normalize.css and Josh Comeau's / Andy Bell's modern resets. Link them before your own CSS.

F) Who wins when rules clash? (specificity)

Which colour am I?

p      { color: crimson; }     /* tag   : weakest  */
.fight { color: royalblue; }   /* class : stronger */
#fight { color: seagreen; }    /* ID    : strongest → WINS */
/* inline style="" beats them all */

Order: inline > ID > class > tag. If two have the same strength, the last one written wins.

  • Tag: global defaults (body, h1, a).
  • Class: reusable components. The one you'll use most.
  • ID: unique elements and anchors.
  • Common mistakes: forgetting the dot (warning instead of .warning), using # instead of ., or a space where there should be none (.a .b ≠ .a.b).

16. Media queries: mobile and desktop

A media query applies CSS rules only when a condition is true, usually the screen width. This is how one page adapts to phones and computers (responsive design).

Needed in the <head> for phones: <meta name="viewport" content="width=device-width, initial-scale=1.0">

Live on this page: resize your browser window

Same HTML + CSS, two screen sizes

Mobile (320px wide)

Desktop (wide)

Mobile-first (recommended)

/* 1. Base styles = MOBILE */
.cards { display: grid; grid-template-columns: 1fr; gap: 8px; }

/* 2. From 600px width and up = TABLET / DESKTOP */
@media (min-width: 600px) {
  .cards { grid-template-columns: repeat(3, 1fr); }
}

Desktop-first (the opposite)

/* Base = DESKTOP */
.cards { grid-template-columns: repeat(3, 1fr); }

/* Up to 600px wide = MOBILE */
@media (max-width: 600px) {
  .cards { grid-template-columns: 1fr; }
}
Device Typical breakpoint
Phone up to ~600px
Tablet ~600px – 1024px
Desktop 1024px and up

Other conditions exist too: @media (orientation: landscape), @media (prefers-color-scheme: dark), @media print. This very page hides the sidebar to the top below 800px.

19. Transitions

A transition makes a change between two states smooth. It needs a trigger (:hover, :focus, :checked, a class added by JavaScript…). 

selector {
  transition: property  duration  timing-function  delay;
  transition: transform .3s ease 0s;
}

Put transition on the normal state (so it also animates back) and the new values on :hover.

1. Colour + lift

.btn { transition: transform .3s, background .3s; }
.btn:hover { transform: translateY(-5px) scale(1.1);
             background: orange; }

2. Image zoom

.wrap { overflow: hidden; }
.img  { transition: transform .5s; }
.wrap:hover .img { transform: scale(1.2); }

3. Underline that grows

Hover this link 
a::after { content:''; display:block; height:2px;
           width:0; background:currentColor;
           transition: width .3s; }
a:hover::after { width:100%; }

20. Animations (@keyframes)

An animation runs by itself, without a trigger, and can have many steps. You define the steps with @keyframes and apply them with animation. 

@keyframes bounce {
  0%, 100% { transform: translateY(0); }
  50%      { transform: translateY(-50px); }
}
.ball {
  animation: bounce 1s ease-in-out 0s infinite;
  /*         name   time timing   delay repeat */
}
Property Meaning
animation-name Which @keyframes to use
animation-duration How long one cycle takes
